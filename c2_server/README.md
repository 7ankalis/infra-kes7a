# C2 Infrastructure Deployment Directory

This directory contains the Infrastructure as Code (IaC) and configuration management files required to deploy a hardened, multi-tier Command and Control (C2) redirector setup on AWS.

## Architecture Overview

The infrastructure implements a tiered redirection strategy to ensure backend obfuscation and operational security (OPSEC):

1.  **Edge Layer (CloudFront):** Provides a high-reputation domain and global CDN presence to mask the true origin of the traffic.
2.  **Traffic Validation (ALB):** Acts as a gatekeeper using a secret custom header to filter out direct scanners and unauthorized requests.
3.  **Backend Layer (EC2 + Nginx):** Hardened Ubuntu instance running Nginx to proxy traffic to the internal C2 framework.


## Deployment Benchmarks

Recorded execution times for a fresh deployment on AWS eu-north-1:

*   **Terraform Provisioning:** ~6m 41s (Latency primarily due to CloudFront global propagation).
*   **Ansible Configuration:** ~0m 57s (System updates and Nginx deployment).

## Directory Structure

### /terraform
*   **versions.tf / variables.tf**: Provider definitions and variable declarations.
*   **main.tf**: EC2 instance, SSH keys, and Security Groups.
*   **alb.tf**: Load balancer, target groups, and secret header listener rules.
*   **cloudfront.tf**: CDN distribution and header injection logic.
*   **outputs.tf**: Displays CloudFront Domain, ALB DNS, and EC2 Public IP.

### /ansible
*   **ansible.cfg**: Ansible settings to disable host key checking and define inventory paths.
*   **setup_c2.yml**: Playbook for system hardening and Nginx reverse proxy automation.
*   **inventory_c2.ini**: Dynamically updated host list generated by scripts.
*   **c2_key.pem**: Private key for server access (generated by Terraform).

### /scripts
*   **update_inventory.sh**: Bridges Terraform outputs into the Ansible inventory.
*   **docker_setup.sh**: Installs Docker environment on the C2 server.
*   **mythic_install.sh**: Automates Mythic C2 installation and initialization.

## Deployment Workflow

### 1. Provision Infrastructure

```bash
cd terraform
terraform init
terraform apply -auto-approve
```

### 2. Sync Inventory

```bash
cd ../scripts
bash update_inventory.sh
```

### 3. Configure C2 Server

```bash
cd ../ansible
ansible-playbook setup_c2.yml
```

## Operational Security (OPSEC)
*   **Secret Header:** The Application Load Balancer (ALB) is configured to drop any request missing the pre-shared secret header with an HTTP 403 Forbidden.

*   **Direct Access Prevention:** The EC2 Security Group only allows ingress on port 80 from the ALB's internal IP range. Direct attempts to reach the EC2 public IP will result in a connection timeout.

*   **Header Manipulation:** CloudFront is the only component that knows the secret header, ensuring that all traffic must pass through the CDN edge locations.

*   **Fingerprinting Protection:** Nginx is configured with `server_tokens off` to suppress version disclosure, and host key checking is handled via `ansible.cfg` to allow for rapid, automated deployment.

*   **Logging:** Custom log formats are recommended in Nginx to capture `X-Forwarded-For` headers to identify the true origin of beacon traffic.

## Cleanup
To tear down the entire infrastructure and avoid ongoing AWS costs:

```bash
cd terraform
terraform destroy -auto-approve
```
